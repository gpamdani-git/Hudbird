## Overview

This directory contains **plans** for improving and building the motion and transition library for Hudbird. Plans follow the `improve-animations` `PLAN-TEMPLATE.md` format and incorporate `transitions-dev` and `transitions-polish` tokenized animation standards.

Plans are organized into two categories:

1. **Motion Component Plans** — Improvements to existing Hudbird motion components (`MotionReveal`, `MotionStagger`, etc.)
2. **Transition Component Plans** — New reusable transitions using the `transitions.dev` motion-token scale

## Missed Opportunities (from transitions-dev audit)

These are places that don't animate but should (additive, not corrective):

- **M1** `AgentArtifactCanvas` — chart (AreaChart/BarChart) has no entry/exit animation when data changes between scenarios.
- **M2** `InteractiveBentoShowcase` — Slider value updates instantly; could spring-animate the label number.
- **M3** Core components and charts — no `prefers-reduced-motion` handling; motion should respect `prefers-reduced-motion` (drop transform, keep opacity/color).

## Token & Standards References

- **`quietEase`**: `[0.22, 1, 0.36, 1]` — repo's shared easing cubic-bezier.
- **Duration budgets** (AUDIT.md §2): UI animations under 300ms. Button press: 100–160ms. Dropdowns: 150–250ms.
- **transitions-dev escalation triggers**: `transition: all`, `scale(0)`, `ease-in` on UI, UI duration > 300ms, `transform-origin: center` on trigger-anchored elements, keyframes on toasts/toggles, layout properties, ungated `:hover` motion.
- **transitions-dev token categories** (from transitions.dev library):
  - `duration`: `xslow` (800ms), `slow` (400ms), `medium` (200ms), `fast` (150ms), `xfast` (100ms)
  - `easing`: `ease-out`, `ease-in-out`, `linear`
  - `physicality`: `scale-from-trigger`, `transform-origin`, `never-scale-0`
  - `interruptibility`: `transition-not-keyframes`, `spring-for-gestures`
